# 算力集群作业调度系统使用指南

## 1. 调度系统概述

本文档介绍算力集群调度系统的配置策略、队列管理规则和资源分配算法，帮助用户高效提交和管理计算作业。

## 2. 调度架构

### 2.1 系统组件

| 组件 | 版本 | 说明 |
|------|------|------|
| Slurm | 23.02 | 主调度器 |
| Maui | 3.4.1 | 高级调度插件 |
| GRES | - | GPU 资源管理 |
| cgroups | v2 | 资源隔离 |

### 2.2 资源池配置

**总资源容量：**
- GPU 数量：4096 张 (A100/H100)
- CPU 核心：32,768 核
- 内存总量：128 TB
- 存储配额：见存储系统说明

**资源分区：**

| 分区名称 | GPU 数量 | 节点数 | 主要用途 |
|----------|----------|--------|----------|
| debug | 128 | 16 | 开发和测试 |
| batch | 1024 | 128 | 批量训练任务 |
| prod | 2048 | 256 | 生产级训练 |
| interactive | 128 | 16 | 交互式作业 |
| inference | 768 | 96 | 推理服务 |

## 3. 资源分配算法

### 3.1 Fair-Share 调度策略

调度器采用 **Fair-Share (公平分享)** 算法分配资源，确保各用户/项目按权重比例获取资源。

**算法原理：**
```
用户优先级 = BasePriority × (1 - UsageFactor)

其中：
- BasePriority: 基础优先级 (由项目等级决定)
- UsageFactor: 历史资源使用比例 (0.0 - 1.0)
  = 实际使用时长 / (当前时间 - 账户创建时间)
```

**权重配置：**
| 项目等级 | 基础权重 | 最大并发作业数 | 单作业最大 GPU |
|----------|----------|---------------|----------------|
| P0 (战略项目) | 1.0 | 50 | 512 |
| P1 (核心业务) | 0.8 | 30 | 256 |
| P2 (一般业务) | 0.5 | 15 | 64 |
| P3 (实验项目) | 0.3 | 5 | 16 |

### 3.2 抢占策略

当高优先级作业需要资源时，系统支持 **抢占式调度**：

**抢占规则：**
1. 仅允许同级或更高优先级作业抢占低优先级作业
2. 抢占时保留被抢占作业的 checkpoint
3. 被抢占作业自动重新排队，保留原始优先级
4. 每分钟最多允许 10 次抢占操作

**时间片配置：**
| 作业类型 | 时间片长度 | 抢占冷却时间 | 最大重试次数 |
|----------|------------|--------------|--------------|
| debug | 30 分钟 | 5 分钟 | 3 次 |
| batch | 60 分钟 | 10 分钟 | 5 次 |
| prod | 无限制 | - | 0 次 (不抢占) |

**抢占补偿：**
- 被抢占作业获得 1.2x 优先系数
- 抢占方需等待被抢占作业 checkpoint 完成
- 最大等待时间：10 分钟

## 4. 队列配置

### 4.1 队列参数

**debug 队列：**
- 资源预留：128 GPU
- 最大运行时长：2 小时
- 最大并发作业数：20
- 调度优先级：最高
- 适用场景：代码调试、小规模测试

**batch 队列：**
- 资源预留：1024 GPU
- 最大运行时长：72 小时
- 最大并发作业数：100
- 调度优先级：高
- 适用场景：离线训练、数据处理

**prod 队列：**
- 资源预留：2048 GPU
- 最大运行时长：336 小时 (14 天)
- 最大并发作业数：50
- 调度优先级：普通
- 适用场景：大规模预训练、微调

**interactive 队列：**
- 资源预留：128 GPU
- 最大运行时长：8 小时
- 最大节点数：4
- 交互模式：支持 srun 实时交互
- 适用场景：数据探索、模型分析

### 4.2 作业优先级计算

作业最终优先级由以下因素综合决定：

```
JobPriority = FairShare × ProjectWeight × QueueWeight × AgeFactor × RequestFactor

因子说明：
- FairShare (0.1-1.0): 账户公平分享因子
- ProjectWeight (1-10): 项目权重
- QueueWeight (1-3): 队列权重
- AgeFactor (1.0-1.5): 等待时间因子 (每小时 +0.02)
- RequestFactor (0.8-1.2): 资源请求合理性因子
```

## 5. 调度超时机制

### 5.1 超时策略

| 参数 | 默认值 | 可配置范围 | 说明 |
|------|--------|------------|------|
| 作业最大运行时长 | 24h | 1min - 336h | 超出自动终止 |
| 无响应检测间隔 | 5min | - | 检测死锁作业 |
| 超时缓冲时间 | 5min | 1-30min | Grace period |
| 自动检查点间隔 | 30min | 10-120min | 周期性保存状态 |

### 5.2 超时处理流程

```
1. 作业运行时间达到 95% 限制
   → 发送警告通知 (邮件 + 短信)

2. 作业运行时间达到 100% 限制
   → 进入 grace period (默认 5 分钟)

3. Grace period 结束
   → 发送 SIGTERM 信号 (优雅终止)
   → 等待最多 60 秒完成 checkpoint

4. SIGTERM 后 60 秒仍未退出
   → 发送 SIGKILL 信号 (强制终止)
   → 保存最后 checkpoint
```

### 5.3 自定义超时

用户可在作业脚本中指定超时时间：

```bash
#!/bin/bash
#SBATCH --time=48:00:00        # 最大运行 48 小时
#SBATCH --time-min=24:00:00    # 最短运行 24 小时
#SBATCH --signal=B:TERM@60     # 提前 60 秒发送 SIGTERM
```

## 6. 亲和性调度

### 6.1 亲和性规则

**GPU 亲和性：**
- 同节点 GPU：优先分配 NVLink 互联的 GPU
- NUMA 亲和：GPU 绑定到对应 NUMA 节点
- 内存亲和：分配与 GPU 同 NUMA 节点的 CPU 和内存

**网络亲和性：**
- 多节点作业：优先分配同叶交换机的节点
- 跨节点通信：自动选择最小跳数路径

### 6.2 亲和性配置示例

```bash
# 分配同节点 8 块 GPU
#SBATCH --gres=gpu:8
#SBATCH --ntasks=8
#SBATCH --ntasks-per-node=8

# 分配 2 节点，每节点 4 块 GPU
#SBATCH --gres=gpu:4
#SBATCH --nodes=2
#SBATCH --ntasks-per-node=4

# 强制同叶交换机节点
#SBATCH --switches=1
```

### 6.3 资源预留

支持提前预留资源，确保关键作业执行：

```bash
# 预留 7 天后的资源
salloc --begin=2026-06-01T00:00:00 \
       --gres=gpu:64 \
       --nodes=8 \
       --time=168:00:00
```

## 7. 作业监控与控制

### 7.1 常用命令

| 命令 | 功能 |
|------|------|
| sinfo | 查看集群状态和分区信息 |
| squeue | 查看作业队列和状态 |
| scontrol show job | 查看作业详细信息 |
| scancel | 取消作业 |
| sreport | 生成资源使用报表 |

### 7.2 作业状态

| 状态码 | 含义 | 说明 |
|--------|------|------|
| PD | Pending | 等待调度 |
| R | Running | 运行中 |
| CG | Completing | 正在结束 |
| CD | Completed | 已完成 |
| F | Failed | 失败 |
| TO | Timeout | 超时终止 |
| NC | NodeCrash | 节点故障 |

### 7.3 资源使用报表

每周生成资源使用报告，包括：
- 各用户/项目的 GPU 小时消耗
- 队列利用率统计
- 作业等待时间分布
- 资源碎片率分析
